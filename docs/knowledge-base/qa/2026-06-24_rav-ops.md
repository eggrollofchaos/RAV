# RAV Operations Q&A

## Coordination

### How should agents get current RAV state?

Read `docs/coordination/live_repo_summary.md` first, then the relevant
retrospective or KB entry. Run `$coord-update pull` at session start when the
overlay is present. Per-session shift notes are local and ignored; durable
truth graduates into live summary, history, retrospectives, KB, and PM files.

### Which files were seeded for RAV coord-update?

- Local overlay: `.claude/skills/coord-update/overlay.local.md`
- Tracked live summary: `docs/coordination/live_repo_summary.md`
- Tracked history: `docs/coordination/repo_summary_history.md`
- Tracked template: `docs/coordination/shift_coordination_note_template.md`
- Ignored shift notes: `docs/coordination/shift_coordination_note__*.md`

The overlay uses `backlog_dialect: "flat-list"` because `pm/backlog.md` is a
dated bullet list, not an index-table backlog.

## Active Follow-Ups

### What is the next model-quality action?

Run the CheXpert validation threshold sweep, save frozen validation-tuned
thresholds, and evaluate test with those thresholds. This is already tracked as
P0 in `pm/backlog.md`.

### Is Sean workstation the default training venue?

No. It is a CUDA smoke/iteration lane. Use it when the job fits the RTX 4080,
disk headroom, and workstation-use etiquette. Use GCP when data locality,
reproducibility, unattended runtime, or larger storage matter.
